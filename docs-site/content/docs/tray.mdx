The release binary is one executable: `struggletime`. Tray, CLI, daemon, and
local HTTP server all live inside it. Download from
[GitHub Releases](https://github.com/derekified/struggletime/releases).

## CLI

```bash
struggletime apikey <st_…>
struggletime start --repo ~/my-project
struggletime status
struggletime pause
struggletime resume
struggletime sync
struggletime stop
struggletime link --repo ~/my-project
struggletime logs
struggletime server          # show or set API URL
struggletime config          # settings path
struggletime verify --ledger .aitime-ledger.json
```

Settings live in `~/.config/struggletime/settings.json`. `start` re-launches
the same binary as `struggletime daemon` (or `STRUGGLETIME_DAEMON` if set).

## Daemon and server

```bash
struggletime daemon --repo ~/my-project
struggletime serve           # http://127.0.0.1:18765
```

## Tray

```bash
struggletime tray
# force supervisor-only (no menu-bar icon):
struggletime tray --headless
```

On **macOS** and **Windows**, `tray` opens a menu-bar / notification-area icon
using the StruggleTime SVG, tinted from your colourscheme (`theme` in
`settings.json`, default `classic`):

| State | Icon colour |
|---|---|
| Tracking | theme `--accent` |
| Paused | theme `--trust-yellow` |
| Idle | theme `--mut` |

Menu (same layout as the old Python tray):

- Status / Today (read-only)
- set / link API key…
- get API key in browser…
- clear API key
- link / create project…
- create project…
- start tracking / stop tracking
- open dashboard
- inspect what would be sent
- settings…
- quit

On **Linux**, or if the graphical tray cannot start, it runs a headless
supervisor that prints the same status line and keeps the daemon alive.

Login autostart: `sh daemon/autostart.sh`.

## Privacy

Only allowlisted metadata is synced. After a seal, open
`.aitime-ledger.json` in the project folder, or run `struggletime logs`.
