The release binary is one executable: `struggletime` / `struggletime.exe`.
Tray, CLI, daemon, and local HTTP server all live inside it. Download from
[GitHub Releases](https://github.com/derekified/struggletime/releases). See
[Installation](/docs/installation) for App + PATH setup on each OS.

## App mode vs CLI mode

| How you launch | What happens |
|---|---|
| Double-click / Start Menu / Applications / `struggletime --tray` | Tray icon + background tracker supervisor (no extra console on Windows) |
| Terminal with a subcommand (`status`, `apikey`, `serve`, …) | Normal CLI on stdout/stderr, then exit |
| Terminal with no args (interactive TTY) | Prints `status` |

App and CLI share settings, API key, linked projects, and the hash-chained ledger.

## CLI

```bash
struggletime --version
struggletime apikey <st_…>
struggletime start --repo ~/my-project
struggletime status
struggletime pause
struggletime resume
struggletime sync
struggletime stop
struggletime link --repo ~/my-project
struggletime logs
struggletime server          # show or set API URL
struggletime config          # settings path
struggletime verify --ledger .aitime-ledger.json
struggletime adapters list
struggletime adapters install
struggletime adapters install vscode neovim
struggletime --help
```

`adapters install` copies editor/agent helpers into the usual user paths
(VS Code/Cursor extensions, Neovim packpath, Claude Code hooks, Codex wrap,
shell hooks). Project kits (Godot / Unity / JetBrains) are vendored under
`~/.config/struggletime/adapters/` with symlink instructions. The tray menu
item **install adapters…** runs the same install.

Settings live in `~/.config/struggletime/settings.json`. `start` re-launches
the same binary as `struggletime daemon` (or `STRUGGLETIME_DAEMON` if set).

## Daemon and server

```bash
struggletime daemon --repo ~/my-project
struggletime serve           # http://127.0.0.1:18765
```

## Tray

```bash
struggletime --tray
struggletime tray
# supervisor only (no icon; prints status):
struggletime tray --headless
```

On **macOS** and **Windows**, and on **Linux** release builds with AppIndicator,
the tray opens a menu-bar / notification-area icon using the StruggleTime SVG
(transparent background), tinted from your colourscheme (`theme` in
`settings.json`, default `classic`):

| State | Icon colour |
|---|---|
| Tracking | theme `--accent` |
| Paused | theme `--trust-yellow` |
| Idle | theme `--mut` |

Menu:

- Status / Today (read-only)
- set / link API key…
- get API key in browser…
- clear API key
- link / create project…
- create project…
- start tracking / stop tracking
- open dashboard
- inspect what would be sent
- install adapters…
- settings…
- quit

If the graphical tray cannot start, StruggleTime falls back to a headless
supervisor that keeps the daemon alive.

### Auto-start on login

```bash
sh daemon/autostart.sh
```

- **macOS:** LaunchAgent → `struggletime --tray`
- **Linux:** `~/.config/autostart/struggletime.desktop` (+ optional user systemd unit)
- **Windows:** `install.ps1 -Autostart` writes a Startup-folder shortcut

## Privacy

Only allowlisted metadata is synced. After a seal, open
`.aitime-ledger.json` in the project folder, or run `struggletime logs`.
File paths are stored as `sha256(salt:path)`. Each sealed bucket points at the
previous one with `prev_hash`.
