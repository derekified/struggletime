Integrations are optional and self-hosted. With nothing configured, filesystem tomography still runs.

## Shell hooks (exec categories)

Hooks emit command category events (`test`, `build`, `run`). They never send arguments or environment secrets.

```bash
# bash / zsh
source /path/to/struggletime/daemon/hooks.sh

# PowerShell
. C:\path\to\struggletime\daemon\hooks.ps1
```

IDE/agent adapters follow the same rule: category and timing metadata only. Thin adapters live under `adapters/` (VS Code family, Neovim, Godot, JetBrains, Unity, Claude Code, Codex, OpenClaw). See [Daemon](/docs/daemon) for the full table and cache/lock ignore list.

## GitHub

### Connect with OAuth

1. GitHub -> Settings -> Developer settings -> OAuth Apps -> New OAuth App
2. Authorization callback URL: `https://your-server/v1/auth/github/callback` (local: `http://127.0.0.1:18765/v1/auth/github/callback`)
3. Start the server with `GITHUB_CLIENT_ID` and `GITHUB_CLIENT_SECRET` (env, `.env`, or secret store; never committed)
4. In StruggleTime Settings, use "sign in with github", approve on GitHub, land back linked

The server exchanges the one-time code, reads your GitHub login, and discards the OAuth token. Only the username is stored. The manual endpoint `POST /v1/users/{handle}/github` still exists for tests and automation. The login appears on your public profile and in the builders list.

### Repo webhooks (push -> commit anchors)

1. On your repo: Settings -> Webhooks -> Add webhook
2. Payload URL: `https://your-server/v1/integrations/github/webhook`
3. Content type `application/json`, events: `push` only
4. Set a secret and start the server with the same value: `GITHUB_WEBHOOK_SECRET=... python3 server/server.py`

`server.py` verifies the signature (bad signature -> 401), matches the push to the project whose repo URL matches, and stores a commit anchor: commit count and head SHA only. Commit messages are never stored. Anchors appear on `GET /v1/projects/{id}/github` for review cross-checks. With no secret set, webhooks are accepted unverified (fine locally, not on the public internet).

### Live repo lookup (optional)

`GET /v1/projects/{id}/github?fetch=1` fetches stars/branch/last push from the GitHub API. Set `GITHUB_TOKEN` to raise rate limits. Off unless you ask for it; the server does not phone home on its own.

## Slack

### Notifications

Set `SLACK_WEBHOOK_URL` (Slack app -> Incoming Webhooks) before starting the server. New submissions and finished reviews post to that channel. If unset, the same messages queue locally and stay readable at `GET /v1/integrations/events`.

### OAuth and slash command

For identity: Slack app -> OAuth & Permissions -> redirect URL `https://your-server/v1/auth/slack/callback`, then start the server with `SLACK_CLIENT_ID` and `SLACK_CLIENT_SECRET`. In StruggleTime Settings, use "sign in with slack", approve, land back linked. The code exchange happens server-side; only your Slack user id is kept.

1. In the same Slack app: Slash Commands -> `/struggletime`
2. Request URL: `https://your-server/v1/integrations/slack/command`
3. Automation fallback: `POST /v1/users/you/slack {"slack_user_id":"U0123ABCD"}`
4. Start the server with `SLACK_SIGNING_SECRET=<signing secret from the app Basic Information page>`

`/struggletime stats` replies only to you with weighted hours, streak, and bucket count. `/struggletime stats somehandle` looks up a handle. Forged signatures get 401. With no secret set, the command works unsigned for local testing.
