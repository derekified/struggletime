## Process model

`daemon/daemon.py` is a background process that uses only the Python standard library. No third-party packages, browser automation, or accessibility APIs for screen content.

```text
every ~1s
  |- poll linked project folders
  |- watch saves, git activity, and known build/test caches
  |- optional adapter/exec events (hooks, IDE plugins)
  |- update active work window + idle clock
  |- seal time slices -> append local log -> offline queue -> sync
```

Start via tray, helper, or:

```bash
python3 daemon/daemon.py --repo /path/to/project
```

## Multi-project afternoons

Link multiple repos with the tray or `struggletime-helper link`. The loop watches all linked roots. When you switch trees, credit follows the project that is actually changing. You do not need to stop and start for each repo.

## What counts as “active”

Billable time is the **active span**: contiguous seconds where the tracker sees meaningful change (git updates, file saves, test/build category events, adapter heartbeats). Leaving the daemon running while you do nothing does not bill.

| Signal class | Examples (metadata only) |
|---|---|
| Git activity | `HEAD`, index, packed-refs, reflog mtime/inode |
| Filesystem | Scrambled file IDs, size class, mtime deltas |
| Cache / build | Known tool cache footprints (compile, test, package) |
| Adapter / exec | Category tags (`test`, `build`, `run`); never command arguments |

## Quiet reading after real work (5–12 minutes)

After you fix something you often stare at a stack trace without typing. `src/verify.py` applies a tapered weight (`SILENT_*` curve) instead of dropping to zero immediately:

- Full credit while the quiet window is short
- Gradual scale-down between roughly 5 and 12 minutes of silent follow-up
- Same curve on daemon and server

This replaces the old hard cliff where `idle_secs >= 240` forced weight to zero. Rules YAML may still mention `idle_pause_secs: 240` as a reference. Live weighting uses the gradual curve (`tests/test_daemon_tracking.py::test_no_idle_cliff_at_240`).

## Idle cutoffs

After the active span ends, remaining quiet time decays toward idle. `verify.py` labels `IDLE` when that curve has exhausted credit. Long unattended gaps do not accumulate struggle hours.

## Sealing time slices

1. Aggregate events into a time bucket.
2. Run `verify.weight_bucket` and stamp `FORMULA_VERSION`.
3. Append to the local log (`.aitime-ledger.json`) with `prev_hash` linking to the previous entry.
4. Enqueue for `POST /v1/buckets/batch` when online.

## What the tracker never does

- Capture screens, keystrokes, clipboards, or microphones
- Read or upload file contents or raw prompts
- Store command-line arguments
- Send unhashed absolute paths

See [Privacy](/docs/privacy).

## Editor / agent labels (Layer 1)

`daemon/editors.py` maps running processes to `editor` / `agent` labels. Built-ins cover the VS Code family, JetBrains IDEs, Neovim, Helix (`hx`), Godot, Unity, KiCad, Blender, FreeCAD, OpenSCAD, Aseprite, Krita, GIMP, Figma, Xcode, Arduino IDE, Jupyter, RStudio, Obsidian, plus common CLI agents. Override without code changes via `~/.config/struggletime/editors.json`.

## Optional adapters (Layer 2)

Adapters append allowlisted lines to `~/.aitime/agent_events.jsonl` (counts and labels only). The daemon drains that file each poll tick, then falls back to process signatures. There is no MCP server.

| Adapter | Adds | Setup |
|---|---|---|
| `adapters/vscode` | Human edits, focus, file-op counts | Load `extension.js` |
| `adapters/claude-code` | Agent turn boundaries | Merge `hooks.json` |
| `adapters/codex` | CLI turn boundaries | Shell wrapper / README |
| `adapters/openclaw` | Session turn / tool counts | Run `adapter.py` |
| `adapters/neovim` | Insert vs external edits, focus, saves | `require("struggletime").setup()` |
| `adapters/godot` | Focus, filesystem edits, playtest | Enable `addons/struggletime` |
| `adapters/jetbrains` | Typing vs bulk writes, window focus | Build the Kotlin scaffold |
| `adapters/unity` | Focus, asset saves, play mode | Drop `Editor/StruggleTimeTracker.cs` |

Legacy `~/.aitime/exec.jsonl` is still drained for older hooks. If an adapter breaks, Layer 1 keeps counting.

## Cache / lock ignores

The tracker skips tool caches and lock files so they do not look like bulk agent writes:

- Godot: `.godot/`, `*.import`
- Unity / Unreal: `Library/`, `Temp/`, `Obj/`, `Intermediate/`, `Saved/`, `Binaries/`
- KiCad / CAD: `~*.lck`, `*-bak`, `*-backups/`, `fp-info-cache`
- Blender: `*.blend1`, `*.blend2`
- Xcode / JetBrains: `DerivedData/`, `xcuserdata/`, `.idea/`

## Debug mode

Enable allowlisted diagnostics with either the env var or the CLI flag (same effect):

```bash
STRUGGLETIME_DEBUG=1 python3 daemon/daemon.py --repo ~/my-project
python3 daemon/daemon.py --debug --repo ~/my-project
```

`AITIME_DEBUG=1` is accepted as an alias. Adapters honor the same env. Logs print labels only (`editor`, `event_type`, counts) — never paths, prompts, or argv.

## Verification

```bash
python3 scripts/verify_adapters.py
# or
make verify-adapters

python3 -m unittest tests.test_daemon_tracking tests.test_editors tests.test_ecosystem_adapters tests.test_adapters_e2e -v
python3 -c "from src import verify; print(verify.FORMULA_VERSION)"
```

`scripts/verify_adapters.py` loads each adapter under `adapters/` and checks emit → drain paths without uploading source.
