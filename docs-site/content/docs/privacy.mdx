## Guarantees

| Guarantee | Detail |
|---|---|
| Stdlib-only daemon | `daemon/daemon.py` imports only the Python standard library |
| No screen / keystroke / prompt capture | No screenshots, OCR, keylogs, clipboard, or transcript text |
| No content / argv | File bodies and command arguments never leave the machine |
| Salted file IDs | On-wire identity is `sha256(salt:path)` hex, not absolute paths |
| Schema budget | Allowlisted JSON fields only; typical sealed bucket ~25-50 KB |
| Hash chain | Each ledger entry carries `prev_hash` linking to the prior seal |

## What never leaves the machine

- Raw prompts, agent transcripts, chat logs
- Source file contents and unhashed absolute paths
- Command-line arguments and environment secrets
- Screenshots, window pixel buffers, microphone audio
- Keystroke streams or clipboard history

## Salted file IDs

```text
file_id = hex(sha256( f"{salt}:{absolute_or_repo_relative_path}" ))
```

Salt is local/config-scoped. The server sees opaque IDs and size/mtime classes, not path strings. An intercepted bucket does not reconstruct your tree as readable paths.

## Allowlisted schema

`POST /v1/buckets/batch` validates against a strict allowlist. Unknown fields are rejected.

| Field class | Examples |
|---|---|
| Identity | `user` / key binding, `project_id`, `formula_version` |
| Time | bucket start/end, active span seconds |
| Structure | salted file IDs, event category counts |
| Integrity | `prev_hash`, entry `hash`, sequence |
| Weight | computed weighted seconds / state labels |

Payloads stay small (~25-50 KB) because they carry metadata counts and IDs, never source blobs.

## Hash-chained ledger (`.aitime-ledger.json`)

Local append-only log (per project or configured path):

```text
entry_n.hash = H( canonical(entry_n without hash) )
entry_n.prev_hash = entry_{n-1}.hash
```

Quiet rewrite of an old bucket breaks the chain for everything after it. Reviewers can flag `CHAIN_BROKEN`. The server tracks a chain head; clients adopt that head after a successful flush so multi-device stays aligned.

## Offline queue and sync

```text
seal locally -> append ledger -> enqueue
                     |
        online? -----+--- no -> keep queue on disk
                     |
                     +--- yes -> POST /v1/buckets/batch (ordered)
                                <- adopt server chain head
```

Flush is ordered. Partial failures leave unacked entries on the queue for retry. `struggletime-helper status` and the tray show last sync success or failure.

## Server retention

- Soft-deleted / anonymized analytics paths filter PII where applicable
- Review reason codes describe patterns (idle inflation, dump), not pasted secrets
- Builders leaderboard opt-out is in Settings (see [Web app](/docs/web-app))
